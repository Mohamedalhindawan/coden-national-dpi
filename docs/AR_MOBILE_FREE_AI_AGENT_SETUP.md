# تشغيل وكيل ذكاء اصطناعي لـ CODEN من جوال أندرويد — مسار مجاني

**الحالة:** دليل عملي، وليس ادعاءً بأن وكيلًا مستقلًا يعمل حاليًا في الخلفية.
**القيود:** لا لابتوب، لا API key، لا اشتراكات مدفوعة، ولا بيانات حقيقية للمستفيدين.

## الخلاصة الصريحة

لا توجد طريقة مضمونة لتشغيل وكيل برمجة مستقل كامل مجانًا وعلى مدار الساعة من الهاتف فقط، من دون مفتاح نموذج أو حصة سحابية متاحة. برامج الوكلاء مفتوحة المصدر لا تجعل استدلال النموذج أو الخادم السحابي مجانيًا تلقائيًا.

المسار القابل للتطبيق الآن هو سير عمل مساعد بالذكاء الاصطناعي:
- ChatGPT للمساعدة في تحديد المهمة وكتابة التغييرات ومراجعتها ضمن الإمكانات المتاحة في المحادثة.
- GitHub لإدارة الملفات والفروع وطلبات الدمج.
- GitHub Actions لتشغيل الاختبارات والتحقق من العقود.
- الإنسان يراجع التغييرات ويقرر دمجها.

هذا ليس وكيلًا مستقلًا يعمل وحده؛ إنه أقرب مسار مجاني وعملي حتى تتوفر بيئة تشغيل مجانية حقيقية أو حصة وكيل مؤهلة في الحساب.

## الأدوات

| الأداة | الاستخدام | هل يلزم دفع الآن؟ | الحدود |
|---|---|---|---|
| GitHub Mobile / Web | فتح المستودع، مراجعة التغييرات وطلبات الدمج | لا، ضمن الميزات المجانية | واجهة الجوال صغيرة |
| ChatGPT | تحليل المتطلبات، إعداد تعديلات محدودة، مراجعة واختبارات | استخدم الوصول الحالي فقط | لا يضمن تشغيل وكيل دائم أو تنفيذ كل المهام تلقائيًا |
| GitHub Actions | اختبارات آلية عند التغييرات أو التشغيل اليدوي إذا كان مفعّلًا | قد توجد حصص وحدود | لا يشغّل وكيل LLM تلقائيًا بمجرد وجود workflow |
| GitHub Copilot Free | مساعدة برمجية ضمن الحصص المتاحة | يمكن تجربة الخطة المجانية إن ظهرت لحسابك | ميزات الوكيل والحصص تتغير؛ لا تفترض توفر coding agent السحابي |
| Codespaces | بيئة تطوير سحابية من المتصفح | حصة مجانية محدودة إن كانت متاحة | لا يوفر نموذج AI مجانيًا تلقائيًا، والحصة تنفد |
| Ollama | تشغيل نماذج محليًا | البرنامج مجاني | يحتاج جهازًا قادرًا على تشغيل النموذج؛ لا يحل مشكلة الهاتف وحده |
| Codex CLI / Aider | وكلاء برمجة في بيئة طرفية | البرامج مفتوحة المصدر | يحتاجان بيئة تشغيل ونموذجًا متاحًا؛ تثبيتهما وحده لا يعني أن الاستخدام مجاني |

## سير العمل من الجوال

1. اختر Issue صغيرة ومحددة في مستودع CODEN.
2. حدّد معيار قبول واضحًا قبل التعديل.
3. استخدم ChatGPT لصياغة الحل أو تنفيذ تعديل محدود عبر تكامل GitHub المتاح.
4. ضع التغيير في فرع مستقل أو طلب دمج عندما تكون الإمكانية متاحة؛ لا تدمج تغييرات حساسة تلقائيًا.
5. شغّل workflow `Prototype checks` من تبويب Actions إن ظهر خيار `Run workflow` وكانت لديك الصلاحية.
6. افتح سجل التشغيل وتأكد من أن الاختبارات نجحت فعلًا.
7. راجع الفرق (diff) قبل الدمج. إذا فشل الاختبار، أصلح السبب قبل الانتقال للمهمة التالية.

## أول مهمة مناسبة

ابدأ بتحسينات صغيرة في نموذج Tamam الثابت الذي يستخدم بيانات اصطناعية فقط. لا تضف الآن:
- بيانات مستفيدين حقيقية.
- قرارات أهلية فعلية أو صرف مدفوعات.
- مفاتيح API أو كلمات مرور في المستودع أو المحادثات.
- صلاحيات نشر إنتاجي أو دمج آلي غير خاضع للمراجعة.

## متى ننتقل إلى وكيل مستقل؟

ننتقل فقط بعد التأكد من وجود واحد من الآتي:
1. ميزة وكيل سحابي مفعلة بالفعل في حساب GitHub/ChatGPT.
2. بيئة تطوير سحابية مجانية ذات حصة واضحة، مع نموذج متاح ضمن الخطة نفسها.
3. ميزانية يوافق عليها صاحب المشروع صراحةً.

قبل منح أي وكيل صلاحية كتابة للمستودع، نستخدم أقل صلاحيات ممكنة، ونبدأ بفرع تجريبي، ونمنع الوصول إلى الأسرار والبيانات الحقيقية.
