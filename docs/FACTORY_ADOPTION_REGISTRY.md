# GitHub Open Source Adoption Registry

Snapshot taken 2026-11-20 UTC. Adopt = use an existing component as supplied. Integrate = connect a component to a tested factory entry point. Customize = maintain a documented upstream delta. Build = implement the remaining CODEN-specific contract. Reject = exclude from this pilot; revisit if the recorded constraint changes. A classification expresses a decision; the evidence column or linked registry gives its verification status.

## Inventory and method

Base #124 (26ba063), stacked on #118 and #116, supplies intake, zero-budget review, SQL coding/QA and the read-only Agents API artifact adapter. Main (921b2b8) supplies Tamam, OpenAPI, architectural records, governance and CI. #26 includes draft scheduling, FinOps, policy sandbox helpers and simulated model routing. Its sandbox helper explicitly performs path authorization only. #125 has the CLI context helper and customized GitHub CI skill on #117. These branches have separate review histories. This PR extends #124 without merging the other branches. The narrow project runner executes specialist steps serially; use #26 as the starting point for durable queueing, DAGs and cross-worker admission.

Searched GitHub repositories by functional requirement (SQL parsing, Python workflows, ADRs, offline testing, secret scanning, documentation, packaging and diff review). Cross-checked results against established implementations, upstream READMEs, license texts, build/dependency manifests, revision dates and published GitHub advisories. Irrelevant search hits were screened out. Compared tool inputs, output portability, maintenance surface, online access, privileges and resource requirements. One local model and one new Python runtime dependency passed the adoption gate. The table includes host components used by reference. The review is scoped to reachable interfaces; the absence of a public advisory is not a security certification.

## Eight-team requirements and choices

| Testing | **Adopt** Python unittest and JSON comparisons. **Integrate** fresh, network-isolated processes per case. **Reject** pytest and Hypothesis for this fixture set: additional plugins/generation offer no required capability yet. | Source acceptance run, independent package holdout, regression tests and negative controls. |
| Security | **Integrate** Ruff, bubblewrap and prlimit. **Build** scoped AST and intake policies. Ruff findings, unsupported code or unavailable sandbox stop execution. | Bound inputs, read-only filesystem, empty environment, separate network namespace and bounded resources verified in tests. |

| Review | **Integrate** a separate run of the actual packaged executable against withheld inputs. **Adopt** GitHub PRs for the human decision. **Reject** reviewdog for now: remote comments would need additional permissions. | Review receipt binds the exact archive hash. ## Alternatives and prior evaluations

The earlier [pinned Codex registry](https://github.com/Mohamedalhindawan/coden-national-dpi/blob/8fd3e85aa4de8ea4897eac6d6e6677711eea7e87/docs/codex-integration-registry.md) retains source, licenses and rationale. Decisions here: **Customize** openai/skills gh-fix-ci in #125; **Adopt** the Superpowers TDD procedure; **Reject for this slice** Spec Kit, OpenSpec CLI, Serena, Context7, Repomix, LiteLLM proxy, OpenAI Agents SDK, Codex Action, FreeLLMAPI, Gitleaks and Temporal. OpenSpec and Gitleaks remain pilot candidates; LiteLLM requires approved providers. **Integrate** Ruff here, advancing its earlier candidate status. The Agents SDK is distinct from the existing Agents API artifact adapter. Existing Codex CLI 0.172.0-alpha.2 was inspected; direct cloud inference and CLI compatibility with a local Ollama/LM Studio provider were not tested.
