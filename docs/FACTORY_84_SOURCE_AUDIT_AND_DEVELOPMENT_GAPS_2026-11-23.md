## 3) تراخيص/شروط تتطلب قراراً قبل إدخال الاعتماديات

- **Serena:** ملف `LICENSE` الرسمي يحدد GPL-3.0-or-later للتطبيق، وMIT لمكوّن SolidLSP. يجب مراجعة أثر الربط/التوزيع قبل إدخاله في منتج CODEN.
- **Langfuse:** أجزاء MIT الأساسية مع استثناءات مجلدات `ee/` المرخّصة بشكل مختلف؛ لا نفترض أن كل مكون متاح بنفس الرخصة.
- **LiteLLM:** أجزاء MIT الأساسية مع استثناء `litellm/enterprise/`.
- **FreeLLMAPI:** README الرسمي يصف الاستخدام بأنه **للتجارب الشخصية والتعلّم وليس الإنتاج**. شروط كل مزود API مستقلة؛ لا يعتبر تجميع حصص المزودين أرصدة مملوكة لـCODEN.
- **Hermes Self-Evolution:** `pyproject.toml` يصرّح MIT لكن لم يُرصد `LICENSE` في الجذر؛ يذكر README استهلاك واجهات API وتكلفة لبعض تجارب التحسين. يبقى P2 ولا يُسمح له بتعديل سياسات المصنع ذاتياً.
- **أدوات Copyleft أخرى:** Grafana، k6، Renovate، Plane، Ansible، Semgrep، bubblewrap وغيرها تتطلب فحص الالتزامات عند الربط أو التوزيع؛ وجود GPL/AGPL/LGPL لا يعني منع الاستخدام الداخلي تلقائياً.

هذه **ملاحظات فحص أولية وليست رأياً قانونياً نهائياً**. يجب إضافة حقوق النماذج المفتوحة وأوزان Qwen، تراخيص الحزم المباشرة وغير المباشرة، وتراخيص الصور وبيئات التشغيل إلى سجل الأدلة.

**ممنوع قبل مراجعة خاصة:** Hermes Self-Evolution بأي صلاحيات كتابة ذاتية، APIs مدفوعة، بيانات حقيقية أو مفاتيح إنتاج، إصدار/دمج إلى `main` تلقائياً، أو التنزيل من GitHub `HEAD` دون تثبيت نسخة والتحقق منها.
