# Skill: Technical Architecture Diagramming

## Purpose
Create accurate, editable enterprise and solution architecture diagrams.

## Procedure
1. State diagram purpose, scope, level, actors, boundaries, and assumptions.
2. Use consistent notation for systems, services, data stores, trust boundaries, external parties, and flows.
3. Label arrows with the meaning and direction of data/control flow.
4. Separate current state, target state, and conceptual examples.
5. Show security, identity, governance, observability, and human approval where relevant.
6. Prefer Mermaid, PlantUML, SVG, or native editable shapes over flattened images.
7. Validate names, dependencies, directionality, and consistency against source architecture.
8. Add legend, version, owner, and figure number.

## Acceptance criteria
No ambiguous arrows, no unexplained acronyms, no invented integrations, no misleading implementation status, and editable source retained.
