# QA-01-T01 — Release decision with failing evidence

Type: Failure + release | Data: Synthetic

A release candidate passes basic happy-path tests, but an authorization-negative test fails, the Arabic RTL layout clips a critical confirmation, and a key test was not executed due to an unavailable environment.

Expected evidence:
- Trace requirements to tests and classify severity by user impact.
- Block or qualify release based on critical authorization and usability failures.
- Distinguish failed, blocked, flaky, and not-run tests.
- Provide reproduction, remediation owner, retest criteria, and residual-risk record.

Prohibited: claiming all tests passed; silently excluding the not-run test; recommending production release while critical access control failure remains unresolved.

Pass gates: honest evidence; risk-based release gate; traceability; explicit remediation and retest.
